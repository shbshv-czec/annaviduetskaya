## 2. Как устроено и как публикуется

| | |
|---|---|
| Репозиторий | `github.com/shbshv-czec/annaviduetskaya` |
| Ветка | `main` — она же боевая |
| Деплой | push в `main` → GitHub Pages (из корня ветки) |
| Боевой адрес | https://shbshv-czec.github.io/annaviduetskaya/ |
| Папка проекта | `…/Dropbox/Bots/anna_website/site` |
| Стек | статика: один `index.html` + `assets/`. Сборки нет, зависимостей нет |

Отдельного шага сборки **не существует** — что в репозитории, то и на сайте.
Инструментальной привязки нет: ни конфигов редактора, ни служебных папок.
Скрипты — обычный Python 3 из стандартной библиотеки, без `pip install`.

### Правило публикации

1. `python3 scripts/check.py` — обязательно, **каждый раз перед коммитом**.
2. Коммит и push в `main`.
3. Дождаться деплоя и проверить на живом сайте:
   ```bash
   curl -s "https://shbshv-czec.github.io/annaviduetskaya/?v=$RANDOM" | grep -q "искомая строка"
   ```
   Кавычки обязательны: zsh раскрывает `?` как шаблон.
   «Деплой успешен» может относиться к предыдущему коммиту — сверяй SHA.

Сейчас принято публиковать сразу после прохождения `check.py`.
Если заказчик попросит режим «публикую только по команде» — это надо
зафиксировать здесь отдельной строкой.

### `.nojekyll`

Пустой файл в корне. **Не удалять.** Без него GitHub Pages прогоняет сайт
через Jekyll, а тот игнорирует файлы с подчёркиванием в начале имени —
картинки отдавали 404.

## 3. Структура

```
index.html            весь сайт: разметка + <style> + <script> инлайн (≈130 КБ)
assets/               картинки, видео, шрифты
  fonts/              7 сабсетов WOFF2, свои (не Google Fonts)
  media/              7 логотипов СМИ
  yt/                 обложки роликов YouTube
scripts/check.py      проверка целостности перед публикацией
scripts/update-views.py   обновление счётчиков просмотров YouTube
.github/workflows/update-views.yml   запуск обновления (расписание выключено)
robots.txt, sitemap.xml
.nojekyll             не удалять
```

### Блоки страницы (сверху вниз)

первый экран → бегущая строка с анонсом → книга → цитата «Я так больше
не хочу» → обо мне → публикации в СМИ → консультации → полоса с призывом →
отзывы → выступления → пресс-центр → YouTube → телеграм → подвал.

Два видео «закреплены» через `position:sticky` внутри своей сетки: шоурил
в выступлениях (справа) и главный выпуск в YouTube (слева). Видео стоит,
пока листается соседняя колонка, и уходит вместе с ней, когда низы
поравнялись. Работает только при `align-items:start` у сетки и без
`overflow:hidden` у предков; на мобиле отключено.

`check.py` считает 11 секций: цитата, полоса с призывом и подвал — не
`<section>`, а отдельные блоки.

Плюс два наложения: модальное окно формы и плашка cookie.

## 4. Шкала текстов — главное правило вёрстки

Размеры, интерлиньяж и отступы живут **только** в `:root`. Ни один текст
не задаёт себе размер сам. Карта ступеней — комментарий «КАРТА ТЕКСТОВ»
в начале `<style>`; там же написано, какая ступень какими блоками набрана.

| Ступень | Токены | Где |
|---|---|---|
| Супер крупный | `--h-hero` / `--lh-hero` | имя на первом экране |
| Крупный заголовок | `--h-1` / `--lh-h1` | заголовки блоков, цитата, названия форм |
| Обычный заголовок | `--h-2` / `--lh-h2` | подразделы |
| Мелкий заголовок | `--h-3` / `--lh-h3` | карточки, темы, ролики |
| Подзаголовок | `--t-sub` / `--lh-sub` | строка под крупным заголовком |
| Крупный текст | `--t-lg` / `--lh-lg` | вводный абзац |
| Обычный текст | `--t-body` / `--lh-body` | основной текст |
| Мелкий текст | `--t-sm` / `--lh-sm` | галочки согласий, ошибка формы, юр. строка в подвале |
| Капс | `--t-caps` / `--lh-caps` | надзаголовки, метки |

Отступы: `--gap-caps` после капса, `--gap-h` после крупного заголовка,
`--gap-h3` после мелкого, `--gap-p` между абзацами, `--gap-cta` перед кнопками.

**Новый текст сначала относим к ступени, потом ставим класс.** Если
понадобился размер, которого нет в шкале, — это повод обсудить шкалу,
а не дописать `font-size` на месте.

Заголовок **всегда** визуально крупнее соседнего текста. Cormorant мелок
по рисунку: 23px заголовка рядом с 17px текста выглядят одинаково, поэтому
мелкий заголовок поднят до 29px. Числа в шкале подобраны оптически.

Единственное исключение — форма в модальном окне: на низких экранах
шрифты ступенчато ужимаются, иначе внутри появится прокрутка (см. п. 6).

## 5. Дизайн и тексты

Эталон — **parloa.com**: воздушно, премиально, «с остринкой». Не дёшево,
не стандартно.

- Палитра взята с того, как Анна одевается: чёрная кожа, пудрово-голубой,
  красный маникюр. Чернила `--ink:#1F1C1B`, акцент бирюза `--accent:#178A8A`,
  вспышка красным `--spark:#C8322A`, золото `--gold` только у медали Amazon.
- Шрифты: Cormorant (заголовки), Lora (текст), Manrope (UI-капс).
- Единый разделитель на весь сайт: тонкая линия + квадратная засечка слева,
  прочерчивается через `scaleX(0→1)`. Цвета — `--rule` и `--dot`.
- Проявление при прокрутке: классы `.rv` (блюр) и `.rv-up` (подъём),
  вешает IntersectionObserver, каскад через `transitionDelay`.
  **Не заводить вторую систему проявления** — так уже было, два механизма
  переписывали друг друга инлайн-стилями, и блоки оставались замыленными.

### Правила текстов

- Буква **«ё»** в текстах Анны сохраняется как есть. Не заменять на «е».
- Кавычки — **«ёлочки»**.
- Нигде не пишем, что Анна занята или недоступна. Всё от лица команды:
  «мы перезвоним», «мы свяжемся».
- Любая правка текста, дизайна или юридических формулировок — **сначала
  согласовать с Юлией**. Технические исправления делаются сразу.

### Как принято работать

Один пункт — одна правка — проверка. Не всё разом. Не додумывать: если
не хватает данных, спросить. Не плодить дубли — переиспользовать то, что
уже есть (аккордеон, карточки, система кнопок, механика параллакса).

## 6. Технические ограничения, которые легко сломать

### Формы

Пять сценариев (`call`, `consult`, `speak`, `book`, `podcast`) живут в одном
модальном окне, поля подставляются по `data-form`. Конфигурация — объекты
`FIELDS` и `FORMS` в `<script>`.

**Жёсткое требование: внутри формы не должно быть прокрутки ни на одном
разрешении.** Поэтому в CSS формы четыре ступени компактности:
`max-width:640px`, `max-height:700px`, `max-width:400px и max-height:700px`,
`max-height:470px` (+ двухколоночная раскладка карточки в альбомной
ориентации от 560px ширины). Трогая форму, перемеряй: 5 форм × 16 разрешений,
от 320×568 до 1920×1080, портрет и альбом.

Размер шрифта в полях ввода — **не меньше 16px**, иначе iOS зумит страницу
при тапе в поле.

**Куда уходят заявки.** `var FORM_ENDPOINT = ''` — пока пусто. Форма
собирает данные и открывает WhatsApp с готовым текстом, чтобы заявка
не терялась. Когда появится свой приёмник, вписать адрес — форма пошлёт
POST с JSON: `{form, name, phone, email, contact, note, consent, privacy, news}`.

### Картинки и видео

- Все `<img>` с `width`/`height`/`alt`/`decoding="async"`, кроме первого
  экрана — с `loading="lazy"`.
- Глобально `img{height:auto}`: иначе атрибут `height` становится CSS-высотой
  и растягивает кадр.
- Видео: `preload="none"` + IntersectionObserver, вне экрана — пауза,
  `playbackRate = 0.85`.
- Фон первого экрана — два WebP: `anna-hero.webp` и `anna-hero-m.webp`.

### Горизонтальная прокрутка

Ширина документа должна совпадать с шириной экрана на всех разрешениях
от 320px. Уже ловили дважды: видео без CSS-размеров внутри `aspect-ratio`
и повёрнутая обложка книги с шильдиком. Проверять замером
`scrollWidth − clientWidth`, а не на глаз.

### Счётчики YouTube

Числа просмотров стоят в HTML готовыми — боты не должны видеть нули.
Автообновление по расписанию **выключено** (`update-views.yml`), включим
после переезда на свой домен; для этого нужно раскомментировать `schedule`
и выставить в Settings → Actions → General права «Read and write».

Репозиторий самодостаточен для работы над сайтом: клонируй, правь, публикуй.

| Мастер (вне репо) | Что из него собрано |
|---|---|
| `back_black.jpeg` | `assets/prism-corner.jpg` |
| `glow.webm`, `glow.mp4`, `glow-poster.jpg` | `assets/quote-glow.*` — фон цитаты |
| `anna_door.mp4` | `assets/door.mp4` |
| `ScreenRecording_08-30-2026 10-39-35_1.mp4` | `assets/tg-scroll.mp4` |
| `logos/` | `assets/media/*.png` |
| `Anna/` | фотобанк, 41 файл — источник портретов |

Пересобрать производные без мастеров нельзя. Если их нет под рукой —
запросить у Юлии папку `anna_website/`.

Рецепты, которые иначе не восстановить:

- **`prism-corner.jpg`** — кроп `back_black.jpeg` (1060, 430)–(2160, 1140),
  отражение по горизонтали, масштаб так, чтобы ядро вспышки встало в правый
  нижний угол кадра. Левый, верхний и нижний края растушёваны; правый край
  оставлен резким — он совпадает с краем секции. Накладывается через
  `mix-blend-mode:screen`, поэтому чёрный фон снимка исчезает сам.
- **`quote-glow.*`** — свечение за цитатой, собрано заранее и подключено
  как есть. Два файла: WebM для Chrome, Firefox и Android, MP4 для Safari
  и iPhone; браузер сам берёт первый, который умеет играть. Петля
  бесшовная: последний кадр стоит за один шаг до первого — если сделать их
  одинаковыми, на стыке будет двойной кадр. Высота 588, а не 587, как
  у фото: MP4 не принимает нечётную высоту. Первый кадр совпадает
  с `quote-glow.jpg`, поэтому эта же картинка стоит фоном секции.
- **`door.mp4`** — камера в исходнике непрерывно наезжает (+1,4% за клип),
  из-за чего петля дёргалась. Компенсация покадровая, коэффициент
  K = 0.001713 на секунду, выведен эмпирически из двух пробных кодировок.
  Склейка: открытие → пауза 1,5 с → закрытие. Шов петли 0,00%.
- **`tg-scroll.mp4`** — 30 кадров/с (на 15 выглядело как гифка), ширина
  540 px, 6,2 с. Конец сшит с началом полусекундным кроссфейдом: без него
  разница на стыке была 49 из 255, сейчас 21,8 — это середина обычного
  разброса между соседними кадрами, то есть петля неотличима на глаз.
- **`assets/media/*.png`** — логотипы СМИ приведены к высоте 96 px и
  квантованы по палитре. Оптический размер каждого задаётся в разметке
  через `style="--h:NNpx"`: это данные о конкретном логотипе, а не оформление.

## 7. Проверка перед публикацией

1. `python3 scripts/check.py` — баланс тегов, задвоенные секции, баланс
   скобок в CSS, слипшиеся правила, дубли селекторов, целостность скриптов,
   невидимые заголовки.
2. Визуально: **390px** (телефон) и **1280px** (ПК), консоль без ошибок.
3. Если трогал форму — прогон по разрешениям на прокрутку.
4. Если трогал вёрстку — замер горизонтальной прокрутки от 320px.
5. После push — проверка на живом сайте через `curl` с антикэшем.

### Как снимать замеры в headless Chrome

Две грабли, на которых уже теряли время:

- **Окно не бывает уже 500px.** `--window-size=390,…` молча зажимается:
  страница верстается как 500px. Узкие ширины снимать только через
  страницу-обёртку с `<iframe width="390">` и флагом
  `--allow-file-access-from-files`.
- **`--dump-dom` отдаёт вьюпорт на 87px ниже заявленного окна**, а
  `--screenshot` — ровно по окну. Всегда печатать фактические
  `innerWidth × innerHeight` в самом замере и доверять им, а не флагу.
- `scroll-behavior:smooth` ломает программную прокрутку в замерах —
  перед `scrollTop` ставить `scrollBehavior='auto'`.

### Технический долг

- **Юридические страницы не сделаны.** Политика обработки ПД и Согласие
  на обработку ПД должны быть отдельными страницами в стиле сайта со
  ссылками из подвала и из каждой формы. Сейчас там заглушки.
  Галочки в формах уже сделаны правильно: не предзаполнены, первые две
  обязательные, третья (рассылка) — отдельная и необязательная.
  Реквизиты оператора в подвале есть: ИП Видуецкая Анна Марковна,
  ИНН 665901553491, ОГРНИП 313774602900460.
- **CSP отсутствует.** Строгая политика несовместима с текущей архитектурой:
  весь CSS и JS инлайн. Чтобы её включить, надо вынести `<style>` и
  `<script>` в отдельные файлы. Решение за заказчиком: это заметная
  переделка ради заголовка, который GitHub Pages всё равно не отдаёт.
- **`_headers` нет** — GitHub Pages не позволяет задавать HTTP-заголовки.
  Файл понадобится при переезде на Cloudflare или Netlify.
- **JSON-LD (Schema.org) нет.** Напрашивается `Person` + `WebSite`.
- **`viewport-fit=cover` и `env(safe-area-inset-*)` не заданы** — на iPhone
  с вырезом шапка и нижние плашки могут вести себя неаккуратно.
- **Критический путь ~290 КБ** без сжатия (HTML 130 + три шрифта 108 +
  мобильное фото 34). GitHub Pages отдаёт gzip, по проводу выходит заметно
  меньше, но до ориентира ТЗ в 200 КБ без сжатия не дотягиваем. Основной
  вес — сам `index.html`, потому что CSS и JS внутри него.
- **Семь инлайн-стилей** `style="--h:NNpx"` на логотипах СМИ (это данные
  о высоте каждого логотипа, не оформление) и один `style="color:…"`.

## 9. Чего делать нельзя

- Удалять `.nojekyll`.
- Чистить CSS диапазонами строк — только по селекторам, живые и мёртвые
  правила лежат вперемешку. После чистки сверить, что у каждого класса
  из HTML остались стили, и глазами проверить все блоки.
- Заводить вторую систему проявления при прокрутке.
- Дописывать `font-size` в обход шкалы.
- Менять тексты, дизайн или юридические формулировки без согласования.
- Публиковать, не прогнав `check.py`.
